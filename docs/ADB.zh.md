# 在原厂 B31 上开启 ADB

[English](ADB.md) | 简体中文

本文说明在**中兴 U60 Pro（MU5250）、CN 原厂 B31 固件**上重新开启 USB ADB 的原理和步骤。
`install.sh` 在遇到锁定设备时会自动做这件事；这里把过程拆开讲清楚，并给出三种方式，供你按谨慎程度选择。

> 只针对你**自己拥有**的、型号和固件都对得上的设备。请先读 [安全说明](SAFETY.md)（英文）。

## 为什么需要

B28 及以后的固件（包括 B31）从 Web 守护进程里删掉了开启 USB 调试的接口（`zwrt_bsp.usb.set` /
`zwrt_bsp.usb.op`），所以网页上没有、也刷不出 ADB 开关。CN B27 及更早的固件还留着这个接口，可以直接开，
不需要本文的步骤。

还能用的是**参数备份 / 恢复**这条路：

- 设备的参数备份是一个用 openssl 加密的 tar 包，里面是系统配置和启动脚本；
- 恢复过程以 **root** 运行，会原样展开你给它的备份。

于是流程就是你记得的那样：**导出备份 → 在备份里插入一行开启 ADB 的启动命令 → 恢复回去 → 自动重启 → ADB 开启**。

## 原理（插入的是什么）

启动脚本 `etc/rc.local` 里会读取 USB 模式节点。工具只在脚本靠前的位置加入**一行**，在开机时把 USB
切到带 adbd 的调试组合，后面所有原始内容保持不变：

```sh
echo 1 > /sys/class/android_usb/android0/usb_op
```

> 这一行是写进**路由器启动脚本**的内容，不是在你电脑终端里执行的命令。sysfs 路径从设备自己的原厂
> `rc.local` 里读出来，不写死；绝不要在运行中手动写这个节点（会把 USB gadget 搞挂，要重启才能恢复）。

插入后，工具按设备自己的格式重新打包（内层 tgz → 重算 md5 → 外层 tgz → 重新加密），这样才能通过恢复时的校验。
整份备份是你几秒前刚导出的，所以除了这一行，其它设置都不变。

## 备份密钥后缀

备份的加密口令是 `<设备 IMEI><后缀>`：

- **IMEI** 是每台设备自己的，工具从设备读取，你不用手输（也不要贴到聊天或命令行里）；
- **后缀**是这一代 ZTE 设备通用的一段固定字符串。应最初发现者的要求**不公开发布**（公开了下个固件就会把它堵上），
  本仓库里也没有它。获取方式：
  - 向社区询问；
  - 或从一台已 root 的同代（SDX75）ZTE MBB 设备上自己提取：Web 服务程序在内存里拼出备份口令，
    在它备份 / 恢复相关代码附近的字符串里能看到这个后缀。

用 `--suffix`、环境变量 `ZTE_BACKUP_SUFFIX`，或交互式（隐藏输入）提供。它不会进入本仓库。

## 方式一：`install.sh` 自动完成（最省事）

大多数人用这个。检测到设备锁定（没有 ADB、没有 SSH）时，`install.sh` 会自动走完整个解锁，再接着装 OpenUI。

```sh
bash install.sh --dry-run     # 先试运行：只检查，不写入设备
bash install.sh               # 正式运行；会先显示要恢复的内容再征得同意
```

它会提示输入路由器管理员密码和备份密钥后缀，先跑解锁工具自己的试运行，没问题后才真正恢复。
设备重启约 60–90 秒后 ADB 开启，安装继续。详见 [安装教程](INSTALL.zh.md)。

## 方式二：只开 ADB，用 `zunlock.py` 脚本

只想开 ADB、暂时不装 OpenUI，就单独跑解锁脚本：

```sh
python3 scripts/zunlock.py --dry-run          # 全流程，只是不上传（安全）
python3 scripts/zunlock.py                     # 正式运行，上传前会再确认
```

它做的事：

1. 用管理员密码登录 Web；
2. 请求并下载一份新的参数备份；
3. 解密（`openssl enc -d -des-ede3-cbc -md sha256`，口令 `<IMEI><后缀>`）；
4. 在 `etc/rc.local` 里插入上面那一行（位置在 shebang 之后），保留文件权限和属主；
5. 按设备格式重新打包、重新加密；
6. 确认后上传（`/cgi-bin/cgi-upload`，校验服务器返回的 sha256），触发 `device_restore_proc`——设备恢复并重启；
7. 约 60–90 秒后，`adb devices` 列出设备，`adb shell` 进 root。

后缀用 `--suffix` 或 `ZTE_BACKUP_SUFFIX` 提供，不写死；`--keep-work DIR` 可保留中间产物。

## 方式三：完全离线、自己手动恢复（最谨慎）

如果你不想让脚本替你上传和触发恢复，可以让它只生成**打好补丁的备份文件**，恢复这一步你自己在原厂网页上做：

```sh
python3 scripts/zunlock.py --dry-run --keep-work ./unlock-work
```

- 它仍会登录网页、下载并在本机打补丁，但**不会上传、不会触发恢复、不会重启**；
- 补丁后的备份写在 `./unlock-work/back_parameter.patched`。

然后你自己来恢复：

1. 再次确认这份备份来自**这台设备、当前配置、原厂 B31**；
2. 在原厂网页的「参数备份 / 恢复」里，选择 `back_parameter.patched` 恢复**一次**；
3. **恢复过程会自动重启路由器并短暂断网**。不要因为网页断连就重复点恢复，等重启完成再看状态。

这条路把「改哪一行」和「什么时候写回设备」分开，便于你先检查补丁、再亲手恢复。

## 验证

用支持数据传输的 USB 线连接，电脑装好 Android platform-tools，然后：

```sh
adb devices -l
```

看到设备后（把下面的序列号换成实际列出的那一个）：

```sh
adb -s 实际序列号 shell id
```

- 只有列出状态为 `device` 才说明 ADB 可用；
- `unauthorized` 要在设备上处理授权；`offline` 或空列表先查线材、驱动和 USB 枚举，不一定是恢复失败；
- 权限以 `id` 实际返回为准，不能从「文件校验通过」推断拿到了 root。

## 安全须知

- 恢复会重启设备并短暂断网（约 90 秒），请保证供电稳定；
- **绝不要**在运行中手动写 `usb_op` 节点（会使 USB gadget 失效，需重启）；
- **绝不要**折腾 A/B 槽切换（`abctl --set_active`），混槽启动可能变砖；
- 保留一份**未修改的原始备份**；只用你刚从**这台设备**导出的备份，不要用别人的、旧固件的或来源不明的；
- 开机自启的 ADB 会在重启后暴露调试接口，只连可信电脑，别把调试端口暴露到公网；
- 装完 OpenUI 后，建议改用 2222 端口的只认密钥 SSH；重启后 USB 恢复为普通网络共享，ADB 关闭。

安装 OpenUI 后关于 USB 模式、恢复和回滚的更多说明见 [DEPLOYMENT.md](DEPLOYMENT.md)（英文）。

# IMEI / NV：受保护的双界面事务

> **开发功能，尚未实机验收。** 当前实现和离线测试不等于已证明本机 ABI、真实 NV 写入、恢复或重启后的持久性。开发期间没有执行真实 helper、改号或重启。仅限你拥有或获明确授权的设备，并遵守当地法规和运营商条款；不用于冒用他人设备身份。

## 实现范围

- OpenUI：信号详情中的 IMEI 入口；DevUI：信号块中的 IMEI 入口。两端操作同一后端事务，不能并发各写一份。
- 不是改网页显示，也不是假 `set_imei`。使用固定版本的公开、MIT 许可 DIAG/NV/EFS helper；不使用未经验证的 AT 写号指令，不提供任意 NV、分区或熔丝写入。
- 生产适配仅接受固定的 MU5250 B31 身份、动态库与构建清单。型号、固件、库哈希、helper、清单或读取结构不符即拒绝，不提供强制跳过。
- NV record 0 / 1 是原生记录编号，**不能直接等同物理 SIM 槽**。第二记录未被可靠确认存在时，不启用第二记录编辑；不自动生成第二个号码。
- 目标必须是 15 位 ASCII 数字、非全零、Luhn 有效。原始记录也须安全读取并校验；异常原值不是放宽写入检查的理由。原始/目标结构、尾部及配置长度均有严格约束。
- 可保留某条原值；最终目标不能重复或全部不变。**目标也不能等于另一记录的原值**：这包括交换两个号码，以免中断后产生重复的半写入状态、阻断严格恢复。

原先安全文档中“所有 IMEI 都是 QFPROM 熔丝锁定”的绝对说法缺乏型号级证据，已改正。这不意味着可以写熔丝、解锁分区或保证所有 MU5250 都能改。

## 安装边界

普通发布安装仍不自动安装该开发功能的 helper；已有 v1.2.2 发布包不包含这项功能。使用本开发源码的安装选项：

```sh
# 在包含此功能的源码根目录；先满足源码安装工具链及备份要求。
bash install.sh --from-source --with-imei --update --dry-run
# 核对输出后，才由设备所有者决定是否真正安装：
bash install.sh --from-source --with-imei --update
```

这两条是**供用户审阅的安装命令，不是开发期间已执行的操作**。源码安装需要 Zig 0.14.1、cargo-zigbuild 等现有工具链，见[安装说明](INSTALL.zh.md)。`--dry-run` 可下载、编译并生成本机文件，不代表能验证路由器 ABI。

也可在主机离线构建及核对组件，不连接设备、不执行组件：

```sh
python3 tools/imei-native/build.py
python3 scripts/prepare-imei-helpers.py tools/imei-native/build
```

版本、许可、源文件固定校验和及动态链接要求见[原生工具说明](../tools/imei-native/README.md)。不要替换成来源不明的第三方可执行文件。部署安装器与 IMEI 事务共享排他锁；进行中的 IMEI 操作未安全结束时，安装、更新或部署回退会拒绝继续。

## 正常流程：每一步都由用户明确触发

1. **CHECK / 检查**：鉴权后执行原生只读能力检查。打开页面、轮询状态、按数字键盘“确定”，均不会代替 CHECK 或写号。
2. **输入与预览**：按记录选择保留原值或输入目标，生成带短有效期、绑定当前 revision 的预览。
3. **风险确认 + 第二次确认**：阅读网络中断、重启及私有备份说明，明确确认开始。后端先持久保存并复核原始 NV、原始/候选配置与清单，才开始准备配置。
4. **第一次重启**：界面显示需要重启后，由用户再明确确认。重启会中断管理网络；不要关闭电源、换固件或盲目重复点击。
5. **继续**：设备回来后刷新并按当前事务允许的“继续”。后端复核身份、boot、记录、备份和配置，再执行已确认的原生写入事务并恢复临时配置。
6. **第二次重启**：再次由用户明确确认。
7. **验证**：重连后执行验证，只有原生 NV 与 API 回读一致、临时配置已恢复且满足重启边界，才报告成功。发送成功、HTTP 200 或排队 ACK 都不是改号成功。

正常更改预计需要两次重启；恢复原值也可能需要额外重启。没有自动重启、页面加载写号、启动后自动续写，或者网络超时后的自动重发。客户端本地时间不必与路由器墙钟同步，但本地过期响应、旧 revision、过期预览和不明状态仍拒绝。

## 恢复与不确定结果

- 超时、崩溃、取消或设备状态不明后，先刷新状态；不要把同一操作重复当作全新任务提交。
- 已开始的操作由持久 journal 绑定。只开放该状态允许的明确“恢复备份 / 取消 / 重启 / 验证”，不以猜测修复未知记录或未知配置。
- **重要例外披露**：一次明确确认的原生 `--apply-plan` 事务内部，固定上游 helper 在某些确认失败/中断分支可限次尝试写回已知原值；这属于该原生事务的有界逆操作。外层控制器仍进入显式恢复，不会跨崩溃自动重放、无限重试或自动重启。不能宣传“错误后绝无额外 NV 写入”。
- 已接受计划的逐记录原值/目标混合态可进入显式恢复；任何未知字节、损坏备份或不符身份都拒绝。旧的跨记录危险计划即使哈希自洽，也拒绝加载，不删除原始备份。
- B31 已知 live 配置模式 `0x8d00` / `0x8d20` 允许原生重建/重启造成的有限互换；这不是放宽任意权限或格式。预览源绑定、备份绑定和其他模式仍严格匹配。

## 私有备份与隐私

原始材料保留在设备的 root 私有目录 `/data/openui-imei/operations/<operation_id>/`，当前 journal 在 `/data/openui-imei/current.json`。它们包含敏感标识和原始记录；不要上传 GitHub、公开日志或聊天截图，也不要在恢复完成前删除或手动编辑。目录/文件使用严格权限、校验和、排他锁和持久化写入；**不是加密保险箱**。设备存储损坏或丢失仍可能失去备份，应通过你信任的加密管理通道另行保存到私有主机，并核对传输结果。

UI 的目标预览及操作日志只用遮罩，实际读取的原值可在已鉴权界面显示。退出页面或终态会清除临时输入；浏览器、设备和拥有 root 的管理员仍属于信任边界。

## 验证等级

本次交付覆盖：纯合成事务/崩溃恢复、原生 helper 假 DIAG 测试、校验清单、API/IPC 语法、双界面合成预览、构建、安装锁与既有功能回归。它**不覆盖**真实设备 DIAG 初始化副作用、原生库 ABI、NV 写后持久化、实际恢复成功、运营商接受程度或断电恢复。需要独立且明确授权的实机验收后，才能把它称为“这台机器已验证可用”。

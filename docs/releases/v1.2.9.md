# v1.2.9 — New DevUI, node-measured Cloudflare picks, steadier relay / 全新 DevUI、经节点实测的优选 IP、更稳的中继

简体中文 · English

## 简体中文

**入口：** 已有安装更新使用 `bash install.sh --update --release v1.2.9`；首次安装见 [本版本安装教程](https://github.com/wgltony/U60Pro-OpenUI/blob/v1.2.9/docs/INSTALL.zh.md)。本版本改动了 agent、网页和触摸屏程序（lpac、mihomo 与 v1.2.8 相同）。触摸屏程序更换后需要重新通过设备恢复验证才能打开，安装流程与 v1.2.8 相同。

1. **DevUI 重新设计：**
   - 正文换成平滑的矢量字体（思源黑体 Noto Sans SC，OFL），原点阵字体只作符号后备；圆角加了抗锯齿。触摸屏程序因此从约 8 MB 增大到约 16 MB。
   - 首页改成状态页：顶栏是运营商、信号格和电池；状态卡片显示当前上行（移动数据，或 Wi-Fi 中继及其网络名）、实时网速、代理状态和在线设备数；下面是带分类图标的功能入口；“原厂界面”移到底栏。
   - 新配色，颜色含义固定：蓝色是可点或已选，绿色是正常，黄色是需要注意，红色是故障或危险操作。标题栏改用圆形返回键。
2. **Cloudflare 优选 IP 按节点实测来选：** 边缘上测到的延迟和速度不能代表经过节点后的表现（两个在边缘上相近的机房，经节点后可能差几秒）。现在分两步：
   - 先在边缘粗筛（TCP 连接约 260 个采样地址，对最快的做 TLS 验证并取得机房代号）。
   - 再让决赛地址（正在用的主选和备选、域名解析地址，加上最多 4 个新地址，优先每个机房一个）经一个只监听本机的临时内核真实走节点，测首字节时间和下载。正式测量前先做一次不计分的预热：实测第一个被测的地址总是偏慢。
   - 走不通的淘汰，下载不到最好者一半的淘汰，其余选首字节最低的；正在用的地址除非被明显超过（快 15% 且至少 40 ms）否则不换。第二名作为备选，回退顺序是主选 → 备选 → 原域名。
   - 完整测试每天最多一次；周期到点时只经运行中的内核测一次当前地址的延迟，没明显变慢就跳过。上行在 Wi-Fi 中继和移动数据之间切换后会重测。下载量在 Wi-Fi 中继上每个地址 4 MB，移动数据上 1 MB。
3. **中继更稳：**
   - 频段守护只在中继接口消失满 90 秒后才归还被暂停的频段（中继被关闭时立即归还）。此前 agent 重启、重连或固件重载 Wi-Fi 时，守护会立刻归还并触发第二次重载，把刚建好的中继接口再删掉。
   - 每个保存的网络可选“避开 DFS 信道”，默认关闭。
   - 联网探测加了一个中国大陆以外的地址（Cloudflare），对时加了两个大陆以外的来源。
4. **Clash / WireGuard 接管的设备可以访问 tailnet：** 已被 Tailscale 路由到隧道的带标记流量，在“禁止走 WAN”的拒绝规则之前放行。
5. **降低空闲开销：** 中继的防火墙钩子检查从每 3 秒改为每 15 秒；Tailscale 的状态查询改走守护进程的本地接口，不再每 15 秒启动命令行。
6. **删除双指按住打开 DevUI：** 从设备进入 DevUI 请用电源键连按四次（在网页上开启）或开机自动打开。仍带旧开关的设置文件可以照常读取。
7. TTL 启动脚本以私有权限写入，且只在它是 root 自己的普通文件时才执行。

**验证范围：**
- fmt、clippy（`-D warnings`）、agent 单元测试（实机运行 313 项）、Python 测试 103 项、网页端构建 / lint / 测试 53 项、触摸屏预览自测 13 组全部通过。
- 实机（U60 Pro，B31，经 Wi-Fi 中继、未插 SIM 卡）：替换 agent、守护脚本、网页和触摸屏程序并保留备份，不是经 `install.sh` 全新安装。
  - agent 重启后守护不再归还频段或重载 Wi-Fi；Tailscale 保持在线；tailnet 放行规则出现在防火墙中。
  - 新优选流程自动跑通：6 个候选经节点实测，首字节 438–460 ms，主选和备选保持不变。
  - 触摸屏程序通过设备自检，以及按 `scripts/verify-screen.py` 的步骤手工执行的恢复测试（电源键亮灭、短暂接管后归还、杀掉和冻结界面进程后的恢复）。其中“启动稳定”这一步在新旧程序上都偶发缺失，重试后通过。
- **未在实机验证：**
  - 插卡使用移动数据时的优选流程与下载量、上行切换触发的重测。
  - 局域网设备经 Clash 访问 tailnet（当时热点上没有客户端）。
  - “避开 DFS 信道”开关打开后的实际连接行为。
  - `verify-screen.py` 中经网页接口开关屏幕和等满闲置时间这两项；电源键连按四次进入新版 DevUI。
  - 新首页的英文版只在预览中看过。

## English

**Entry point:** update an existing installation with `bash install.sh --update --release v1.2.9`; for first installs see the [versioned install guide](https://github.com/wgltony/U60Pro-OpenUI/blob/v1.2.9/docs/INSTALL.md). This release changes the agent, the web panel and the touchscreen binary (`lpac` and `mihomo` are the same as v1.2.8). A replaced touchscreen binary has to pass the device recovery checks again before it opens; installation is the same as v1.2.8.

1. **DevUI redesigned:**
   - Text is set in a smooth outline face (Noto Sans SC, OFL); the bitmap face stays as the fallback for symbols, and rounded corners are anti-aliased. The touchscreen binary grows from about 8 MB to about 16 MB.
   - Home is a status page: carrier, signal bars and battery in the top bar; a card with the uplink in use (mobile data, or the Wi-Fi relay and its network), the live speed, the proxy and the devices online; then the features as tiles with a mark coloured by category. **Stock UI** moves to a bottom bar.
   - A new palette with fixed meanings: blue is yours to tap or chosen, green is working, amber needs attention, red is broken or destructive. The title bar has a round back button.
2. **Cloudflare IP optimization picks by what the node delivers:** latency and speed measured at the edge do not predict performance through the node (two data centers alike at the edge can be seconds apart through it). Two stages now:
   - A coarse pass at the edge (TCP connects to about 260 sampled addresses, a TLS check of the fastest that also names the data center).
   - The finalists (the pick and backup in use, the domain's own answer, and up to four new addresses, one per data center first) carry a real request and a short download through a throwaway core that listens on loopback only. A warm-up that is not counted goes first: whatever is measured first is always slow.
   - Addresses that carry nothing are out, as are those under half the best download; the lowest time to first byte wins, and the addresses in use stay unless clearly beaten (15% and at least 40 ms). The runner-up becomes a backup: pick, then backup, then the domain.
   - A full run at most once a day; a due run in between is one delay check through the running core. A change of uplink between the Wi-Fi relay and mobile data starts a run. Downloads are 4 MB per address on the relay and 1 MB on mobile data.
3. **A steadier relay:**
   - The band guard gives a paused band back only after the relay interface stayed away for 90 s (at once when the relay was turned off). Before, an agent restart, a reconnect or a firmware Wi-Fi reload made it restore at once and start a second reload that removed the new relay interface.
   - Each saved network can be told to avoid DFS channels; off by default.
   - The online check gains an endpoint outside mainland China (Cloudflare), and clock sync two sources outside it.
4. **Devices that Clash or WireGuard routes reach the tailnet:** marked packets Tailscale already sent to its tunnel are accepted before the reject that keeps them off the WAN.
5. **Less idle work:** the relay checks its firewall hooks every 15 s instead of every 3 s, and Tailscale status comes from the daemon's local API instead of a CLI started every 15 s.
6. **The two-finger hold is removed:** from the device, open DevUI with four presses of the power key (switched on in the web page) or at startup. A settings file that still carries the old switch loads as before.
7. The TTL startup script is written privately and run only when it is root's own regular file.

**Validation boundary:**
- fmt, clippy (`-D warnings`), the agent's unit tests (313, run on the device), 103 Python tests, the web build / lint / 53 tests and the 13 touchscreen preview self-test groups all pass.
- On a real U60 Pro (B31, on the Wi-Fi relay, no SIM): the agent, guard script, web panel and touchscreen binary were replaced with backups kept; this was not a fresh `install.sh` installation.
  - After agent restarts the guard no longer gave the band back or reloaded Wi-Fi; Tailscale stayed online; the tailnet accept rule was in the firewall.
  - The new optimization ran on its own: six finalists measured through the node, 438–460 ms to first byte, pick and backup kept.
  - The touchscreen binary passed its device self-test and the recovery checks of `scripts/verify-screen.py` carried out by hand (backlight off and on, a short takeover handed back, recovery after the panel process was killed and after it was stopped). The "startup settled" step was missing now and then with both the old and the new binary, and passed on a retry.
- **Not checked on the device:**
  - The optimization and its download sizes on mobile data with a SIM, and the run a change of uplink starts.
  - A LAN device reaching the tailnet through Clash (no client was on the hotspot).
  - Joining behaviour with "avoid DFS channels" switched on.
  - The web open/close and full idle-time parts of `verify-screen.py`; opening the new DevUI with four presses of the power key.
  - The English home screen was only seen in the preview.

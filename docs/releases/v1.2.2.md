# v1.2.2 — Installation and recovery audit / 安装与恢复审计

简体中文 · English

## 简体中文

**入口：** 在本仓库根目录运行 `bash install.sh --release v1.2.2`；已有安装更新使用 `bash install.sh --update --release v1.2.2`。见 [本版本安装教程](https://github.com/wgltony/U60Pro-OpenUI/blob/v1.2.2/docs/INSTALL.zh.md)。

1. **严格限定发布来源：** 主入口与旧入口的默认下载均限定本 fork；无法识别或非本 fork 的 origin 不再静默回退上游，改用其他仓库须显式指定 `--repo`。
2. **USB 确认与设备固定：** 锁定设备首次安装前须确认 USB 数据线连接（交互输入 `YES`，非交互显式 `--acknowledge-usb`）；`--adb-serial` 贯穿解锁后等待与部署。确认不是自动线缆检测，Wi-Fi 或空 ADB 列表不能代替 USB 前提。
3. **旧 GUI 默认拒绝部署：** 在线、缓存及离线包均不能证明 fork 兼容性；恢复、上传与激活写入前即拒绝部署，先前检测仍可能读取设备状态。没有合格的 `.dmg` / `.exe` / `.msi` 安装器发布。
4. **源码交叉编译：** 使用 `cargo-zigbuild` / `cargo zigbuild`，预检 ARM64 musl target 与 Zig **0.14.1**，不再依赖隐含的 musl GCC 链接器。
5. **按范围恢复与服务归属：** 新事务记录文件、FOTA / wireless UCI、relay guard 标记及受管 sidecar 运行状态；回滚按变更范围处理，仅操作归属明确的服务。进程身份核对完整 UID、启动时间、可执行文件路径及 inode、全部 NUL 分隔 argv；归属含糊或恢复失败保留 **pending**。FOTA 恢复只接受 `{}` setter ACK 加保存的 UCI 值；未知/错误响应保持 pending，同时仍尝试恢复其他已确认的旧管理服务。旧快照不追溯补齐覆盖范围，也不承诺断电后精确恢复。
6. **凭据只作为数据读取：** 以十六进制读取已有启动脚本，解析多行及 CR/CRLF 字面量；不执行、`source`、`eval` 或展开脚本，动态或含糊凭据拒绝自动保留。
7. **文档与隐私边界：** 修正主机命令的仓库根目录假设；明确电脑会保留私有加密原始恢复备份，临时工作目录可能包含解密配置，备份不保证包含 OpenUI / Tailscale 状态。relay 跨频段策略用于规避已观察到的 AP/STA 冲突，不是绝对硬件限制。
8. **修补依赖：** 两个前端使用 Vite **8.3.5**，安装器测试使用 Vitest **4.1.12**，保留配套依赖修补；Node.js 要求为 `^20.19.0 || >=22.12.0`。

**发布流程：** agent、屏幕与 lpac 的构建统一校验 Zig 0.14.1；组件缺失即失败，只有发布任务持有仓库写权限。所有组件与安全检查通过后仅创建草稿，独立核验资产和 SHA-256 后才公开。

**验证范围：** 本地主机检查通过：已有 Python 套件 84 项、新增发布契约 7 项、离线 ADB 套件 51 项、网页 30 项、安装器 UI 8 项，共 **180 项**；另有格式、shell、API、隐私、发布一致性检查及 agent ARM64 `cargo check`。这些包含主机模拟，并非原生 B31、真实 USB、冷启动或 FOTA 协议验证。当前版本仍需另行授权的备用实机端到端验收。

**前提仍然存在：** 锁定的原厂 B31 首装仍需管理员密码、外部取得的 backup-key suffix、USB 数据线与原厂网页网络连接；本项目不提供 suffix，也不承诺零前提安装。不要为验证而重置或刷写正在工作的设备。

## English

**Entry point:** from this repository root, run `bash install.sh --release v1.2.2`; update an existing installation with `bash install.sh --update --release v1.2.2`. See the [versioned install guide](https://github.com/wgltony/U60Pro-OpenUI/blob/v1.2.2/docs/INSTALL.md).

1. **Strict release provenance:** default downloads in the main and legacy entry points require this fork. Unrecognized or other-fork origins no longer silently fall back upstream; another repository requires an explicit `--repo`.
2. **USB acknowledgement and pinned device:** locked first installs require physical USB DATA cable acknowledgement (`YES` interactively, explicit `--acknowledge-usb` noninteractively). `--adb-serial` remains pinned through post-unlock waiting and deployment. Acknowledgement is not cable detection; Wi-Fi or an empty ADB list cannot prove the USB prerequisite.
3. **Legacy GUI deployment fails closed:** online, cached and offline bundles do not establish fork compatibility. Deployment stops before restore/upload/activation writes; earlier detection may still read device status. No qualified `.dmg` / `.exe` / `.msi` installer is released.
4. **Source cross-compilation:** use `cargo-zigbuild` / `cargo zigbuild`, with ARM64 musl target and Zig **0.14.1** preflight checks rather than an implicit musl GCC linker.
5. **Scoped recovery and service ownership:** new transactions record files, FOTA / wireless UCI, the relay-guard marker and owned sidecar running state. Rollback respects change scope and operates only on identified services. Process identity checks cover full UID, start time, executable path and inode, and all NUL-separated argv; ambiguous ownership or failed recovery remains **pending**. FOTA restoration accepts only a `{}` setter ACK plus the saved UCI value. Unknown/error replies stay pending while restoration of other verified old management services is still attempted. Old snapshots gain no retroactive coverage; exact power-loss recovery is not promised.
6. **Credentials read only as data:** hex-read the installed startup script and parse multiline / CR / CRLF literals without executing, sourcing, evaluating or expanding it. Dynamic or ambiguous credentials cannot be silently preserved.
7. **Documentation and privacy boundaries:** correct repository-root host commands; explain private encrypted original recovery backups retained on the computer and decrypted configuration potentially left in temporary work. Backups do not guarantee OpenUI / Tailscale state coverage. Cross-band relay policy mitigates observed AP/STA conflicts; it is not an absolute hardware limitation.
8. **Patched dependencies:** both frontends use Vite **8.3.5**, installer tests use Vitest **4.1.12**, and accompanying dependency remediations are retained. Node.js requires `^20.19.0 || >=22.12.0`.

**Release pipeline:** agent, screen and lpac builds verify Zig 0.14.1; missing components fail closed, and only the publication job has repository write permission. All component builds and safety checks must pass before creating a draft, which is published only after independent asset and SHA-256 verification.

**Validation boundary:** local host checks passed: 84 existing Python + 7 new release-contract + 51 offline ADB + 30 web + 8 installer UI tests = **180**; also format, shell, API, privacy and release consistency checks, plus agent ARM64 `cargo check`. These include **host simulations**, not native B31, physical USB, cold-boot or FOTA protocol verification. This release still needs separately authorized spare-device end-to-end acceptance.

**Prerequisites remain:** a locked stock B31 first install still needs the admin password, an externally obtained backup-key suffix, a USB DATA cable and network access to the stock web UI. This project does not supply the suffix or promise zero-prerequisite installation. Do not reset or flash a working device merely to qualify this release.

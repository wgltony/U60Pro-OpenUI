# v1.2.7 — Firmware update lock and charging stopped / 固件升级锁与停止充电显示

简体中文 · English

## 简体中文

**入口：** 已有安装更新使用 `bash install.sh --update --release v1.2.7`；首次安装见 [本版本安装教程](https://github.com/wgltony/U60Pro-OpenUI/blob/v1.2.7/docs/INSTALL.zh.md)。本版本改动 agent 与网页（触摸屏程序与 v1.2.6 相同），安装流程与 v1.2.6 相同。

1. **固件升级锁（系统 → 设置，默认关闭）：** 中兴固件可以通过原厂网页、中兴 App、运营商远程管理（TR-069）或自动检查来升级。升级会删除本项目依赖的开机启动项和 SSH 密钥。打开升级锁后：
   - 中兴的 7 个升级服务器在设备的 `/etc/hosts` 中指向广播地址，检查更新会立即失败，也就不会出现“发现新版本”的提示。这些条目带有标记，重启后在 agent 启动前也有效；关闭升级锁时只删除这些条目。
   - 自动升级保持关闭；如果被重新打开，会自动改回关闭。
   - 每秒检查一次 `/cache`：一旦出现升级包，就取消下载并删除。
   - 已经开始的安装不会被中断（中断刷写可能导致设备无法启动），页面只给出提示。
   - 页面显示服务器是否已屏蔽、自动升级状态以及已删除的升级包数量；关闭升级锁需要确认。确实要升级时请先关闭。
2. **停止充电时不再显示“充电中”：** 充电上限或手动停止生效后，只要插着充电器，内核仍报告“Charging”。agent 现在会在充电开关处于停止状态时报告“Not charging”。首页显示“已停止充电”（充满时显示“已充满”），首页与顶栏不再显示闪电图标，触摸屏也不再播放充电动画。

**验证范围：**
- agent 311 项单元测试在实机（U60 Pro，B31）上通过；网页 53 项测试、构建、lint、i18n、API 契约与隐私检查通过；仓库 Python 测试 103 项通过。
- 实机上验证了：打开升级锁后，手动检查更新以“检查失败”结束且没有连接外部服务器；放入 `/cache` 的测试升级包在 1 秒内被删除，升级状态保持空闲；充电上限生效时内核仍报告“Charging”，而 agent 给触摸屏的状态为未充电。部署方式是替换组件并保留备份，不是经 `install.sh` 全新安装。
- **未在实机验证：** 运营商通过 TR-069 推送的升级（由同一套升级包检测覆盖）。
- **已知情况：** 中兴的 `zte_dm` 每次连接失败都会留下一个未关闭的连接（每次检查约 4 个），与屏蔽方式无关，重启后清除。触摸屏上没有升级锁开关。

## English

**Entry point:** update an existing installation with `bash install.sh --update --release v1.2.7`; for first installs see the [versioned install guide](https://github.com/wgltony/U60Pro-OpenUI/blob/v1.2.7/docs/INSTALL.md). This release changes the agent and the web panel (the touchscreen binary is the same as v1.2.6); installation is the same as v1.2.6.

1. **Firmware update lock (System → Settings, off by default):** ZTE firmware can be updated from the stock web page, the ZTE app, carrier management (TR-069) or automatic checks, and an update removes the boot hooks and SSH keys this project depends on. While the lock is on:
   - The 7 ZTE update servers resolve to the broadcast address through tagged `/etc/hosts` lines, so an update check fails at once and no "new version" prompt can appear. The lines also hold after a reboot before the agent starts; turning the lock off removes only them.
   - Automatic updates stay off, and are turned off again if something re-enables them.
   - `/cache` is checked every second: an update package that appears is cancelled and deleted.
   - An install that has already started is never interrupted (cutting off a flash can leave the device unbootable); the page only warns.
   - The page shows whether the servers are blocked, the automatic-update state and how many packages were removed; turning the lock off asks for confirmation. Turn it off before updating on purpose.
2. **No "Charging" after charging stops:** with the charge limit or a manual stop in effect and a charger attached, the kernel keeps reporting "Charging". The agent now reports "Not charging" while the charge switch holds charging off. Home shows "Charging stopped" (and "Full" when full), Home and the status bar drop the bolt icon, and the touchscreen stops its charging animation.

**Validation boundary:**
- All 311 agent unit tests passed on a real U60 Pro (B31). The 53 web tests, build, lint, i18n, API contract and privacy checks passed, as did the repository's 103 Python tests.
- On the device we checked: with the lock on, a manual update check ended as failed without reaching any outside server; a test package placed in `/cache` was deleted within a second and the update state stayed idle; with the charge limit in effect the kernel still said "Charging" while the agent's touchscreen status said not charging. Deployment replaced components with a backup kept; it was not a fresh `install.sh` installation.
- **Not checked on the device:** a carrier-pushed update over TR-069 (covered by the same package watch).
- **Known:** ZTE's `zte_dm` leaves one connection open per failed attempt (about 4 per check) whatever the block address; a reboot clears them. The touchscreen has no lock switch.
